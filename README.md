# Crowdio — Telegram Order Bot

بات انگلیسی سفارش بسته‌های ۵۰۰، ۱۰۰۰ و ۵۰۰۰ ممبر کانال عمومی تلگرام، با پرداخت Telegram Stars و تحویل دستی توسط مدیر.

## اجرا با PHP

به PHP 8.2 یا جدیدتر و افزونه‌های `curl`، `pdo_sqlite`، `openssl` و `ctype` نیاز است. Docker از PHP 8.4 استفاده می‌کند.

```sh
cp .env.example .env
# تنظیم .env روی سرور
docker compose up -d --build
```

برای اجرای مستقیم، متغیرهای محیط را تنظیم و `php bot.php` را اجرا کنید. در اجرای مستقیم، فایل `.env` خودکار خوانده نمی‌شود. Compose همان volume قبلی را در `/app/data` نگه می‌دارد.

| تنظیم | مقدار |
| --- | --- |
| `BOT_TOKEN` | توکن بات از BotFather، فقط در محیط یا Secret |
| `ADMIN_ID` | شناسهٔ عددی مدیر فعلی. مدیر باید گفت‌وگو با بات را شروع کرده باشد. |
| `SUPPORT_CONTACT` یا `SUPPORT` | نام کاربری عمومی، لینک `t.me` یا شناسهٔ عددی حساب واقعی Crowdio. برای رسیدی که شناسهٔ سفارش را در متن پیش‌نویس می‌گذارد، از حساب عمومی قابل‌پیام استفاده کنید. |
| `MEMBER_PACKAGE_PRICE_STARS` | `385` برای حفظ قیمت ثبت‌شدهٔ بستهٔ ۱۰۰۰تایی در کاتالوگ قبلی. مقدار را به‌صورت عدد صحیح مثبت تنظیم کنید. بدون آن بستهٔ ۱۰۰۰تایی غیرفعال است. |
| `DB_PATH` | همان مسیر SQLite قبلی، روی دیسک پایدار و قابل‌نوشتن |
| `RUN_SECONDS` | `0` برای اجرای پیوسته |
| `TERMS_TEXT` | اختیاری. فقط شرایط نهایی سرویس را درج کنید. مقدار خالی متن پیش‌فرض بات را فعال می‌کند. |

قیمت‌های کاتالوگ قبلی برای بسته‌های ۵۰۰ و ۵۰۰۰ به‌ترتیب ۱۹۳ و ۱۹۲۵ استارز هستند. ۳٫۴۹ دلار فقط مرجع نمایشی بستهٔ ۱۰۰۰تایی است. کاربر مبلغ فاکتور را به Stars می‌پردازد. ۳۸۵ استارز از کاتالوگ قبلی آمده و از تبدیل دلار محاسبه نشده است. تلگرام در شرایط Bot Platform، دست‌کاری رشد شبکه‌های اجتماعی را ممنوع کرده است. پیش از فعال‌کردن فروش، انطباق شیوهٔ ارائهٔ سرویس را با [شرایط رسمی تلگرام](https://telegram.org/tos/bot-developers) بررسی کنید.

## خرید، پرداخت و تحویل

New Order → Select Package → Channel → Review → Telegram Stars invoice → Payment received / Awaiting delivery.

آفر و تعداد کل تحویل در فهرست انتخاب بسته برای مشتری واجد شرایط نمایش داده می‌شود. پیش از صدور فاکتور، مشتری کانال، مبلغ Stars، قیمت مرجع بستهٔ ۱۰۰۰تایی و تعداد تحویل را مرور می‌کند. ویرایش یا لغو پیش از تأیید پرداخت، فاکتور قبلی را بی‌اعتبار می‌کند. پیش از تأیید پرداخت، بات کاربر، سفارش، ارز، مبلغ و اعتبار فاکتور را با SQLite تطبیق می‌دهد. ثبت سفارش در صف با پیام موفقیت پرداخت تلگرام انجام می‌شود.

هدیهٔ ۵۰۰ ممبر فقط روی بستهٔ ۱۰۰۰ یا ۵۰۰۰ و فقط برای نخستین خرید واقعی هر حساب اعمال می‌شود. سقف آفر ۱۰ سفارش موفق در مجموع دو بسته است. بستهٔ ۵۰۰ ممبر هدیه ندارد و خرید موفق آن به‌عنوان اولین خرید حساب ثبت می‌شود. صدور فاکتور آفر، یک سهمیه را تا ۱۵ دقیقه رزرو می‌کند. تأیید pre-checkout مهلت رسید پرداخت را به یک ساعت می‌رساند. انقضا یا لغو قبل از pre-checkout سهمیه را آزاد می‌کند. اگر تلگرام پس از آزاد شدن سهمیه یا بی‌اعتبار شدن فاکتور پرداختی بفرستد که شرایط توافق‌شده را دیگر نمی‌توان تحویل داد، بات آن را برای بازپرداخت Stars ثبت می‌کند. در صورت قطعی یا تکرار پاسخ، ثبت سفارش و سهمیه تکرار نمی‌شود. اعلان‌هایی که تلگرام پذیرفته ولی ثبت ارسالشان قطع شده ممکن است دوباره برسند.

رسید شامل شناسهٔ سفارش، کانال، تعداد، مبلغ، وضعیت و دکمهٔ پشتیبانی است. مسیر مدیر با `/queue`، Start processing و Done حفظ شده است. فرمان‌های مشتری `/orders`، `/support`، `/paysupport` و `/terms` هستند.

## پنل مدیر در تلگرام

با همان حسابی که شناسهٔ عددی آن در `ADMIN_ID` تنظیم شده، `/start` یا `/admin` را بفرستید. پنل فقط در گفت‌وگوی خصوصی باز می‌شود. `SUPPORT_CONTACT` مقصد لینک پشتیبانی مشتریان است. اگر حساب پشتیبانی و مدیر یکی است، `ADMIN_ID` باید شناسهٔ عددی همان حساب باشد.

- **Delivery queue** برای سفارش‌های در انتظار و در حال انجام. بعد از تحویل دستی، مدیر در جزئیات سفارش روی Done و سپس Confirm Done می‌زند. سفارش همراه با زمان تکمیل (UTC) ثبت می‌شود و از صف تحویل خارج می‌شود. مشتری پیام تکمیل را می‌گیرد و می‌تواند وضعیت را در My Orders ببیند. اگر ارسال پیام موقتاً شکست بخورد، بات در اجراهای بعدی دوباره تلاش می‌کند.
- **All orders** و **Payments** برای مرور صفحه‌به‌صفحه. برای پیدا کردن سفارش، شناسهٔ سفارش را مستقیماً در بات بفرستید. `/queue`، `/orders` و `/payments` میانبرهای مدیر هستند.
- جزئیات سفارش شامل حساب مشتری، مبلغ، وضعیت تحویل، شناسهٔ پرداخت و زمان پرداخت ثبت‌شده است. زمان پرداخت سفارش‌های قدیمی که دادهٔ آن را ندارند خالی می‌ماند.
- داشبورد تعداد سفارش‌های پرداخت‌شده، خریداران یکتا، استارز ناخالص ثبت‌شده، بازپرداخت خودکار در انتظار و حساب‌های جدید و فعال در هفت روز اخیر را نشان می‌دهد. آمار فعالیت از زمان نصب این نسخه جمع می‌شود. آمار فروش مشتریان حساب مدیر را کنار می‌گذارد و استارز ناخالص معادل موجودی یا مبلغ قابل‌برداشت نیست.

## انتقال از Python

پیش از جابه‌جایی، از SQLite پشتیبان بگیرید و پردازشگر Python را متوقف کنید. تنها یک پردازشگر باید به‌ازای هر توکن روشن باشد. PHP هنگام شروع، ستون‌های جدید را در همان SQLite اضافه می‌کند و سفارش‌ها و offset قبلی را نگه می‌دارد. فاکتورهای Python که هنوز pre-checkout نشده‌اند باید دوباره ساخته شوند. رسید پرداختی که پیش از انتقال تأیید شده با مبلغ و شناسهٔ فاکتور قبلی تطبیق داده می‌شود. فایل‌های Python و تست‌های موجود برای مراجعه و بازیابی قدیمی در مخزن مانده‌اند.

### اجرای محدود GitHub Actions

Workflow ده‌دقیقه‌ای PHP را اجرا می‌کند و در ۳۰ ثانیهٔ آخر فاکتور یا pre-checkout جدید نمی‌پذیرد. Workflow قیمت ثبت‌شدهٔ ۳۸۵ استارز را به PHP می‌دهد و Repository Variable با نام `MEMBER_PACKAGE_PRICE_STARS` می‌تواند آن را تغییر دهد. Push فایل `bot.php` روی شاخهٔ `php-live-test` نیز همین جلسه را شروع می‌کند. این workflow پرداخت واقعی می‌پذیرد و checkpoint رمزگذاری‌شده را در همان `.runtime/orders.enc` ذخیره می‌کند. برای اجرای مستمر از volume پایدار استفاده کنید.

اگر اجرای قبلی روی Actions بوده، ابتدا آخرین SQLite را از checkpoint با توکن فعلی بازیابی و به مسیر volume منتقل کنید. checkpoint با قالب Fernet و کلید مشتق‌شده از همان توکن سازگار است. پیش از چرخاندن توکن، داده را با کلید قبلی بازیابی کنید. برای حالت اختیاری checkpoint راه‌دور، `STATE_REPOSITORY` و `STATE_GITHUB_TOKEN` باید با هم تنظیم شوند. از اجرای هم‌زمان Actions و سرور دائمی برای یک بات خودداری کنید.
